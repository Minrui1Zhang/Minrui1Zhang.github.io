Agent Lightning v1.0: Towards Harnessed Agentic RL

Zhiyuan He 等 · Microsoft / Fudan / Zhejiang / Edinburgh · 2026.08

训练部署时真正执行的 agent，而不只是训练一个简化的交互循环。

[L] p.1
讲者备注

Harness 指管理上下文、工具执行、控制流与错误恢复的运行框架。这里讨论的是 v1.0，不是将早期 Agent Lightning 的算法贡献直接照搬。

Agent Lightning v1.0问题与核心

接上模型 API，就能正确训练吗？

01

问题

harness 掌控交互；训练器只看到一系列模型请求与回答。

02

难点

一次任务会分支、压缩上下文，也可能被拆成多个训练样本。

03

核心

保留真实采样条件，并以 rollout 作为优势与归一化的统计单位。

一次任务执行（rollout） ≠ 一条训练序列（sample）

[L] pp.2–3, §§1–2
讲者备注

本页围绕标题所示问题展开讨论。

Agent Lightning v1.0系统设计

harness 管执行，trainer 管学习

Trainer 发起任务→Controller 启动 harness→Gateway 记录调用→Adapter 构造样本

用 rollout ID 串起请求、奖励和日志；代理保存真实 token 与 log probability。

[L] p.1 Fig.1; pp.9–11 §3
讲者备注

控制平面采用持久状态和事件记录；Controller 是尽力而为的最终一致性。动态打包可以改变数据位置，但不能改变统计归属；同一 rollout 的样本应处于同一次 optimizer update。

Agent Lightning v1.0关键细节 01

文本相同，不代表 token 相同

01

风险

把下一次提示强行换成旧 token，会改变真实采样条件。

02

处理

只在精确 token 前缀匹配时合并；不匹配就开启新样本。

合并率不是目标：先保证条件正确，再复用计算。

[L] pp.3–6 §2.1, Fig.3
讲者备注

论文称条件不一致为 off-policy stitching；它不同于普通的行为策略落后于当前策略。独立训练保留真实条件，但会重复计算共享前缀。

Agent Lightning v1.0关键细节 02

拆成几段，不该改变优势基线

成功 rollout · reward = 1

sample 1sample 2sample 3

失败 rollout · reward = 0

sample 4
01

按 sample 统计

奖励均值变成 (1+1+1+0) / 4 = 0.75。

02

按 rollout 统计

奖励均值为 (1+0) / 2 = 0.50，再关联到各样本。

[L] p.7 §2.2, Fig.4
讲者备注

这里展示均值偏移，不把 mean-centered reward 当作完整 GRPO 标准化优势公式。先计算 rollout 层组统计，避免样本构造改变基线；分支之间如何做信用分配仍未解决。

ARLArena / SAMPO论文 02

多轮强化学习为何会突然崩溃？

ARLArena: A Unified Framework for Stable Agentic Reinforcement Learning

Xiaoxuan Wang 等 · UCLA / UW–Madison · 所提供版本：2026.07

先建立可控实验平台，再定位不稳定来源，最后组合 SAMPO。

[A] p.1, arXiv:2602.21534v3
讲者备注

本页围绕标题所示问题展开讨论。

ARLArena / SAMPO问题与核心

前期涨分，不等于能持续训练

01

问题

早期动作偏离，会改变后续状态；退化轨迹又进入下一轮更新。

02

核心

拆开策略梯度的设计因素，判断哪些更新导致长期失稳。

[A] pp.1–2, Fig.1
讲者备注

曲线是论文特定模型、任务和超参数下的结果，不能推断某方法在所有设置都必然崩溃。

ARLArena / SAMPO实验前提

先清理训练配方，再诊断算法

BC 冷启动→格式处罚→参考 KL 正则→逐方法调参
01

交互任务

ALFWorld、WebShop、Sokoban。

02

工具推理

TIR Math；数学任务配置与交互任务不同。

03

评价重点

成功率之外，跟踪后期方差、合法格式率和更新动态。

[A] pp.4–5 §3; Appendix B
讲者备注

主体多为 4B 设置，另有 ALFWorld 8B 扩展。非数学任务使用 SFT/BC 冷启动，数学从 base 开始且参考 KL 系数为 0；Sokoban 具体 backbone 以附录 Table 6 为准。

ARLArena / SAMPO诊断框架

四个维度，四个具体问题

01

损失聚合

长短序列各占多大权重？

Token mean / Sequence mean
02

IS 与裁剪

旧策略数据允许多大更新？

GRPO / SAPO / CISPO / GSPO
03

过滤与重采样

组内还有相对学习信号吗？

Dynamic sampling
04

优势设计

终局回报能否区分步骤贡献？

GiGPO / EMPG
[A] pp.2–4 §2, Table 1
讲者备注

ST 改变长短样本权重；SAPO 平滑缩放 token 比率；CISPO 裁剪并停止 IS 权重梯度；GSPO 使用长度归一序列比率；GiGPO 组合 episode 与 step 优势；EMPG 以熵重塑信号。

ARLArena / SAMPO关键发现 01

崩溃前，哪些信号一起变化？

负优势 + 低 IS 比率→KL / 梯度异常→格式有效率下降→成功率崩溃

在这些实验中，偏离过大的负样本是重要的失稳来源。

[A] pp.5–7, Figs.2–3
讲者备注

图中 off-policy KL 比较当前策略与行为策略；KL loss 比较当前策略与参考策略。二者不应混称。该诊断不证明所有训练崩溃都由同一原因引起。

ARLArena / SAMPO关键发现 02

限制不可信更新，比一味放宽更有效

01

序列级裁剪

用长度归一的序列概率比，控制整段生成的更新。

02

序列 mask

过滤负优势且比率过低的序列，而非删除所有失败样本。

ALFWorld 成功率原设置加入 sequence mask
SAPO25.16%76.92%
CISPO54.42%78.88%
[A] §4.2, Table 4; Appendix A.2
讲者备注

这里的 mask 实验用于诊断 tolerant clipping 的问题，不把 sequence mask 额外说成 SAMPO 的第四个核心组件。单纯增加 KL 或扩大 mini-batch 在论文测试中不及针对性处理。

ARLArena / SAMPO关键发现 03

细粒度优势与过滤，需要一起看

01

全局 + 局部

终局回报提供整体方向；相同状态下的动作比较补充步骤信号。

02

动态过滤

奖励完全相同的组可能没有相对梯度，但失败样本仍可能有格式信号。

03

组合有条件

状态必须可比较；过滤本身并不保证收益。

GiGPO 的局部优势依赖状态分组，不能直接照搬到任意工具环境。

[A] §§4.3–4.4; Appendix A.3
讲者备注

Table 3 中 DAPO-GRPO 的 Avg 低于 GRPO；DAPO-GiGPO 在前三任务口径优于 GiGPO。不同环境的优势收益不同，不能解释为处处提升。

AKBE论文 03

什么时候，该让模型自己回答？

Efficient Agentic Reinforcement Learning with On-Policy Intrinsic Knowledge Boundary Enhancement

Dingwei Chen 等 · Tencent / CUHK / SMBU · 2026.05

AKBE：用当前策略的成功路径，学习何时需要工具。

[K] p.1, arXiv:2605.26952v1
讲者备注

本页围绕标题所示问题展开讨论。

AKBE问题与核心

只奖励答对，可能越学越爱搜索

01

问题

最终正确性奖励，无法区分必要调用与冗余调用。

02

直接惩罚调用？

容易连必要工具一起压制：调用更少，答案却更差。

03

核心

每题同时试“有工具”和“无工具”，再选择合适的成功轨迹。

优化目标是更合理地使用工具，而不只是少用工具。

[K] pp.1–3, §§1–3
讲者备注

论文将过度依赖外部检索称为 cognitive offloading。Figure 1 跟踪早期已正确样本，不能把其中比例解释为全部训练数据。

AKBE方法概览

当前策略，双路径探测

同一个问题→有工具 / 无工具采样→判断正确性→最多选择一个目标
[K] pp.3–5, Algorithm 1, Fig.2
讲者备注

WT 与 NT 表示对应路径是否至少出现一个正确样本。基础 RL 继续使用有工具轨迹，辅助监督最多每题选一条。无额外教师模型。

AKBE监督选择

四种情况，分别给出信号

有工具成功无工具成功监督目标目的
是否调用最少的正确工具轨迹保留必要工具
是是随机一条正确无工具轨迹减少冗余调用
否是随机一条正确无工具轨迹纠正有害工具路径
否否不加辅助监督保留基础 RL

“无工具失败”只表示本轮未采样到成功，不等于模型绝对不会。

[K] pp.3–5, Algorithm 1, §4.2
讲者备注

分别为 Tool-dependent、Efficiency、Hallucination、Both-wrong。最少调用是在采样到的正确轨迹中取最小，不是全局最优；并列时随机选取。

AKBE训练目标

把成功行为，变成动态辅助监督

L = LRL + λ Laux
01

基础 RL

继续优化任务奖励；可与 GRPO、DAPO、GSPO 等组合。

02

辅助交叉熵

提高选中成功轨迹的概率，屏蔽工具观察 token。

03

每步重新探测

能力在变化，所需工具也在变化；监督不固定在旧检查点。

[K] p.5 §4.3, Eqs.5–6
讲者备注

该式采用最小化损失约定。额外无工具采样有训练开销；论文主要配置有工具 16 条、无工具 8 条，最大工具调用 6 次。

AKBE研究启发

从调用次数，走向真实成本

01

成本要算全

延迟、token、失败风险、依赖链开销，以及额外探测的训练成本。

02

必要前置不能删

03

迁移要重定义

代码或网页任务的“无工具路径”是否可行？正确性怎样验证？
